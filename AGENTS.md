# Agent execution guide

## What this repo is

This repository maintains a collection of extensions for the Pi coding agent.
The published extension table and installation details live in the root [README](README.md#extensions).

## Layout

- `extensions/magpie-provider/` — live Magpie gateway model discovery, built-in Pi API delegation, and automatic native compaction for OpenAI/Codex Responses models with configurable opt-out and exact overrides. Its protocol/replay engine and tests live in `native-compaction/`.
- `extensions/commit/` — a native `/commit` prompt template for self-contained patch series, with loading/contract tests.
- `extensions/recap/` — a native `/recap [focus or time range]` prompt template for returning to a session after a break: goal, recent progress, key decisions, stopping point, and next step, using only context already available to the model.
- `extensions/quality/` — native `/simplify`, `/review`, `/verify`, and `/deslop` prompt templates for bounded cleanup, read-only bug review, evidence-based verification, and AI-slop removal, with shared loading/contract tests.
- `extensions/orca-bridge/` — Orca hook delivery, background activity aggregation in terminal panes, prompt-aware titles, file/diff navigation, and stock Orca compatibility checks; Subagents publishes snapshots through Pi's event bus. Integrations must use released Orca interfaces without modifying Orca.
- `extensions/autoresearch/` — native main-session optimization: baseline harness design and repeated measurement, explicit user approval before bounded iterations, pinned methodology/harness files, session-owned continuation, durable reports, and footer integration. It owns `/autoresearch`; do not also load `npm:pi-autoresearch`.
- `extensions/benchmark/` — benchmarking. `core.ts` is the shared measurement module: running harness commands through Pi's bash tool (one command n times, or two alternately A, B per round), parsing `METRIC name=value` lines, pinning harness files by SHA-256, summarizing samples, and the comparison verdict; it registers nothing with Pi and imports no extension, and Autoresearch imports only `core.ts` from this directory. `index.ts` registers the model-callable `benchmark_compare` tool, which measures one command or compares two and reports each metric's median, range, and sample count, the median change, and a verdict (`inconclusive` with its reason, `no measurable difference`, or B better or worse than A); it stores nothing. `prompts/benchmark.md` is the `/benchmark <what>` prompt template, which has the agent state the claim, check the harness and machine, measure only through `benchmark_compare`, and report the tool's numbers.
- `extensions/loop/` — session-owned recurring prompts, fixed/cron/model-paced scheduling, completion and lifetime limits, and footer integration.
- `extensions/molt/` — `/molt`, which starts a new session that keeps the current model and thinking level.
- `extensions/language/` — `/language`, the response language in top-level TUI and RPC sessions: a default for new sessions in `<agentDir>/language.json`, pinned at a session's first run into a system prompt section, and mid-session switches as hidden per-run messages that leave the cached prefix alone. It publishes a `language` status, which Statusline Footer shows in its bar.
- `extensions/workspace/` — project-closure workspace management (`<cwd>/.pi/workspaces/<name>` with `.pi/workspaces/.gitignore` containing `*`), `/tmp` scratch allowance, `write`/`edit`/`bash` write target guards with interactive approval (`Allow once`, `Allow for this session`, `Allow for this project`, `Deny`) and child-session propagation via `Symbol.for("pi-extensions.child-session-hooks")`, the `workspace` tool (`create`, `list`, `pin`, `unpin`, `release`), `/workspace` (`list`, `gc`, `allow`, `deny`, `pin`, `unpin`), and `PINNED`/`ACTIVE`/`SAFE`/`REVIEW` safety classification with linked `git worktree` cleanup.
- `extensions/statusline-footer/` — a theme-aware Pi statusline footer and its tests.
- `extensions/impeccable/` — complete vendored Impeccable skill 4.8.0 and canonical roles, 26 native prompt templates, managed engine 0.1.18, supported questions/delegation, opt-in detector/management and session-owned live browser transport. `src/` owns runtime adapters; `scripts/transform.mjs` and `scripts/pi-runtime.mjs` deterministically generate `skills/` and `prompts/` from `vendor/impeccable-4.8.0/`. `upstream.json`, the 63-file pristine SHA-256 manifest, Apache-2.0 LICENSE/NOTICE and `LOCAL-PATCHES.md` retain provenance/adaptation history; never hand-edit generated resources or pristine vendor bytes. See `README.md` and `FEATURES.md` for configuration, prerequisites and evidence boundaries.
- `extensions/subagents/` — vendored pi-subagents v0.22.0, explicit scriptable workflows (`SubagentWorkflow`), a local fleet (`recon`, `worker`, `reviewer`, `expert`), integrations, and offline upstream/compatibility tests. Workflow primitives live in `src/workflow/`, structured output in `src/structured-output.ts`, and frontmatter parsing in `src/agent-definitions.ts`. See its `LOCAL-PATCHES.md` before resyncing.
- `extensions/herder/` — durable, verified orchestration of coding runs: an append-only journal per run under `<git-common-dir>/herder/`, model-written workflow scripts in a sandbox, writing steps as git transactions in disposable worktrees, serial integration on hidden `refs/herder/` refs, runtime-computed verification, and delivery to the user's branch only after confirmation. Shared contracts live in `src/types.ts` and limits and defaults in `src/config.ts`; the Pi commands and tools live in `src/adapter/`, built-in roles in `agents/`, script templates in `templates/`, the skill in `skills/herder/SKILL.md`, and the read-only `/herder-improve` and `/herder-simplify` audit skills in `skills/improve/` and `skills/simplify/` (all registered under `pi.skills`). Herder requires git >=2.38.
- `extensions/pika/` — capture and upload of every session entry, `before_provider_request` payload (or `fidelity: context`), child session via the `pi-extensions.child-session-hooks` hook, and Herder journal, goal, and plan to a self-hosted pika server, with a disk spool, cursors, and acknowledged hashes under `<agentDir>/pika/` and the `/pika` status command. Its default export composes the capture with relay and recall; its child-session hook adds only the capture. `credentials.ts` publishes the `pi-extensions.pika.credentials` registry that relay and recall read, so module copies loaded for other cwds share it. `relay/` is pika relay's client: one WebSocket per online top-level session to the pika server (`connection.ts`), the wire contract and model-facing texts (`protocol.ts`), and the shared state and its own child-session hook (`shared.ts`); it receives messages as `relay-message` turns and registers `relay_list`, `relay_send`, `relay_status`, and `/relay`; the shared contract is `services/pika/docs/RELAY.md`. `recall/` reads the owner's past trajectories through the server's agent read API (`{base}/api/agent/v1/`), authenticated with pika's device token: `recall_search`, `recall_read`, and `recall_herder` (Herder runs) in every session, top-level and child alike; `client.ts` holds the HTTP client and its error texts, `format.ts` the model-facing texts and budgets; the server side is "Agent read API" in `services/pika/docs/SPEC.md`. Tests live in `tests/`, with relay's in `tests/relay/` and recall's in `tests/recall/`. It is listed last in `pi.extensions` so its payload capture runs after every other extension.
- `services/pika/` — the pika server: one Rust binary (`pika serve`, `token`, `password`, `reindex`, `export`, `delete`) with ingest, device pairing, password login with server-side sessions, SQLite storage plus a zstd blob store, the read API, the embedded web UI from `web/` (React, Vite, TypeScript, Tailwind), and `src/pricing.rs`, which prices Magpie calls that recorded no cost from a daily models.dev catalog fetch (`PIKA_PRICES=off` keeps tests and scripts offline). The shared contract is `docs/SPEC.md`; Docker and reverse-proxy examples are `Dockerfile` and `deploy/`; end-to-end and performance scripts are in `scripts/`.
- `extensions/writer/` — eight explicit native academic writing prompt templates for conference papers, with loading/contract tests.
- `themes/` — Pi themes; the repository currently contains the `material-bloom` theme.

## Conventions

- Use conventional commits with a scope, for example `fix(subagents): reject stored raw models in scheduled jobs` and `test(extensions): pin error messages and assert rendered output`.
- Workflow scripts run only on an explicit orchestration request. Subagents workflow children share the run cwd and current files, including existing edits and dependencies; `isolation: "worktree"` gives a single child its own worktree when parallel writers would conflict. Await relevant writers before verification.
- Impeccable activation, `npm ci` and safe collection/scoped/package tests never download its engine/browser. Only explicit engine/visual-foundations/E2E checks acquire runtime assets in isolated temporary state and fail missing prerequisites; Chromium requires host libraries (Node 26 POSIX acquisition also needs `unzip`). Upgrades retain every upstream resource/role/command, regenerate through the transform and pass contracts, scoped runtime, actual E2E, package, typecheck and full `npm test`. No native binaries, runtime caches or credentials are committed. Impeccable uses public Agent capabilities without importing Subagents internals, installing a fleet or changing workflow opt-in. SDK 1.5 is tested; peers >=1.3 use explicit capability fallbacks. Keep pika last in `pi.extensions`.
- TypeScript is strict and configured with `noEmit`.
- The pika server builds with stable Rust and `--locked`. Set `CARGO_TARGET_DIR="$HOME/.cache/pika-target"` to share build artifacts across worktrees. `cargo test` and debug builds must not need `web/dist`: without it the UI routes serve a placeholder page, and only release builds embed the UI, so build `web/` first for a release.
- pika (with relay and recall inside it), Subagents, and Herder never import each other; relay and recall read pika's credentials through `credentials.ts`, whose `Symbol.for("pi-extensions.pika.credentials")` registry module copies loaded for other cwds share. Child sessions reach pika only through the `Symbol.for("pi-extensions.child-session-hooks")` Set and the `pi-extensions.session-link` entry; Herder announces runs on the `herder:run` event.
- Commit, Quality, and Writer tests use strict TypeScript with Node's `node --test`; Statusline Footer, Subagents, Herder, and native compaction tests use Vitest.
- `npm run test:herder` uses `extensions/herder/vitest.config.ts` (30 s test and hook timeouts). Herder tests create real git repositories with `tests/support/git-fixture.ts` and remove them in `finally`; agents are the scripted fake runner (`tests/support/fake-runner.ts`) or, in `tests/agents/`, Pi's faux provider. No live provider tests.

## Do not touch

- `node_modules/` — generated dependency state.
- `<git-common-dir>/herder/` — Herder run state (journals, run files, worktrees); change it only through `/herder` commands.
- `refs/herder/` — Herder run refs; never create, move, or delete them by hand.
