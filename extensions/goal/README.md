# Goal

`/goal <objective>` starts working toward one objective in the current TUI or RPC session. `/goal` or `/goal status` shows it; `/goal pause`, `/goal resume`, and `/goal stop` control it. Use `/goal -- <objective>` when the objective starts with a command word. Stop a live goal before replacing it.

`/goal --budget 50000 <objective>` sets an optional token budget; `/goal budget 100000` changes it. The goal counts the current session's assistant input, output, and cache writes, excluding cache reads. It does not measure separately billed child or subagent sessions. This is a soft cap checked at run boundaries, so an ongoing run may exceed it. Increase the budget and resume when exhausted. There is no default budget or time limit.

After each completed agent run, Pi continues toward the objective unless the model calls `goal_update` to report completion, a blocker, or waiting for external background work. For waiting, use `subagentExecutions: [{ id, executionId }]` with the opaque execution IDs returned by background Subagents spawn or resume. Any exact pair wakes the goal, including a completion observed before the wait. Alternatively use a Herder run ID and launch. Legacy `subagentIds` matches any completion for an ID and is ambiguous when that agent is resumed: an earlier unconsumed completion can satisfy a later wait. Without an expected target, resume explicitly. Completion is the model's claim, not independent verification. Repeated identical responses without tool work, or repeated identical failed tool calls and results, pause the goal for inspection. Existing permissions and approval requirements remain in effect; Goal grants no approvals.

Goal refuses to start or resume while Selfdrive is enabled in the same session. Enabling Selfdrive pauses Goal and aborts a Goal-owned turn; turning it off does not resume Goal. Other extensions may schedule work outside Pi's pending-message queue. Errors pause Goal so provider recovery can proceed independently.

State is saved on the current session branch and survives compaction. Active goals restore paused after reload, resume, fork, and tree navigation; use `/goal resume` to restart them. Aborts, errors, queued user input, and dialogs pause the goal. Goal never automatically runs in print mode. A corrupt latest snapshot is reported as an error.

Observed unconsumed completions remain available across manual pause and resume of the same goal, including completions received while paused; these never resume the goal automatically. Consumed completions remain consumed. Stopping or replacing the goal, session change, or branch change resets the in-memory history. Subagent wakeups use the execution ID in completion notifications to distinguish resumed runs and ignore duplicate deliveries. Older notifications without an execution ID fall back to their published details; two completions with identical details are indistinguishable, while a redelivery with changed details may appear new. Resume Goal explicitly if needed. The repeated-failure guard treats a small set of simple shell inspections such as `pwd` and `git status --short` as reads; other successful shell commands reset the guard because they may have made progress.
