# Local patches

This extension is a pinned vendored fork of the released [Impeccable](https://github.com/pbakaus/impeccable) skill/role distribution (`skill-v4.8.0`, commit `414603bf14c7a344edb466bb1f85690c77ce8b7d`, engine `0.1.18`). The pristine snapshot lives in `vendor/impeccable-4.8.0` with a per-file SHA-256 manifest; `scripts/transform.mjs` applies the deterministic Pi transformations below. See `README.md` for the import/upgrade procedure.

Every difference between the upstream files and the files under `skills/` and `prompts/` is produced by `scripts/transform.mjs` and listed here. Nothing is edited by hand after generation.

## T1 patches (vendor + native prompt commands)

### P-1: Portable launcher addresses in the skill

- **Files:** `skills/impeccable/SKILL.md`, every `skills/impeccable/reference/*.md` (including `reference/degraded/*.md`).
- **Change:** replace every occurrence of the project-relative upstream path `.pi/skills/impeccable/scripts` with the portable `<skill-base-dir>/scripts`.
- **Why:** upstream's generated Pi distribution assumes the skill is installed at the project-relative `.pi/skills/impeccable` path. This package installs the skill elsewhere (arbitrary project or relocated package location), so the skill must address its launcher through the skill directory Pi advertises. Pi's skill loader tells the model the skill's `<location>` (its `SKILL.md` path) and to resolve relative references against that directory; `<skill-base-dir>` is defined in the skill's own Setup step as the directory containing `SKILL.md`.
- **Reproduced by:** `scripts/transform.mjs` `localizeSkill()`.

### P-2: Setup step prefers the managed runner, with the absolute launcher as fallback

- **File:** `skills/impeccable/SKILL.md` Setup step 1.
- **Change:** the upstream step is replaced with a portable formulation that:
  - keeps `<skill-base-dir>` as "the directory that contains this SKILL.md (the skill folder)" (upstream's two-level plugin-root parenthetical is removed because this package installs the skill directly);
  - instructs the model to prefer the `impeccable_run` tool with `argv: ["context"]` when it is available;
  - documents the absolute skill launcher `<skill-base-dir>/scripts/impeccable context` (or `<skill-base-dir>/scripts/impeccable.cmd context` on a Windows shell without `sh`) as the clearly documented fallback, resolved from the `<location>` Pi advertises for the skill.
- **Why:** the managed runner resolves, verifies, caches, and executes the pinned engine itself; the launcher remains the supported fallback for runtimes without the extension, and no path is tied to this worktree.
- **Reproduced by:** `scripts/transform.mjs` `SETUP_STEP1_ORIGINAL` → `SETUP_STEP1_LOCAL`.

### P-3: `allowed-tools` frontmatter path

- **File:** `skills/impeccable/SKILL.md` frontmatter.
- **Change:** the `Bash(.pi/skills/impeccable/scripts/impeccable *)` entry becomes `Bash(<skill-base-dir>/scripts/impeccable *)` via P-1's global substitution; the `Bash(npx impeccable *)` entry is retained verbatim as upstream's npm fallback.
- **Why:** keep the declared pre-approved tool patterns portable. Pi treats `allowed-tools` as experimental metadata; no runtime enforcement is claimed.

### P-4: Canonical agent-role definitions exposed through the skill

- **Files:** `skills/impeccable/reference/agents/{impeccable-asset-producer,impeccable-documenter,impeccable-finish-reviewer,impeccable-manual-edit-applier}.md` (new files, not present in the generated Pi distribution).
- **Source:** `vendor/impeccable-4.8.0/source/agents/*.md` (upstream `skill/agents/*.md`), which upstream's Pi generator does not emit (it emits only the degraded inline fallbacks under `reference/degraded/`).
- **Change:** resolve the source template placeholders `{{scripts_path}}` → `<skill-base-dir>/scripts` and `{{reference_path}}` → `<skill-base-dir>/reference`. Preserve generic instructions and provenance frontmatter (`name`, `description`, `model`, `effort`, `max-turns`). T3 compiles out the `<codex>…</codex>` imagegen block for Pi; the generic native-image preference and API fallback remain complete.
- **Why:** canonical texts remain instruction resources consumed by `impeccable_delegate`, alongside the upstream degraded fallbacks. Frontmatter is retained as source metadata, not installed as fleet configuration; only the role turn ceiling is used as the adapter budget and the exact Agent soft steering request.
- **Reproduced by:** `scripts/transform.mjs` `localizeAgent()`.

### P-5: Native prompt templates generated from command metadata

- **Files:** `prompts/impeccable.md`, `prompts/design.md`, and `prompts/design-<command>.md` for each of the 24 entries in the vendored `scripts/command-metadata.json`.
- **Change:** generated Markdown native prompt templates. Descriptions and `argument-hint` come verbatim from `command-metadata.json`; the body is a routing preamble that locates the skill through its advertised `<location>`, follows the skill's Setup (preferring `impeccable_run`), routes the request, and passes user input through native `$ARGUMENTS`. `adapt` and `audit` additionally name their `.native.md` playbook for iOS/Android targets.
- **Routing fix (T1 reviewer finding):** the freeform template no longer references `reference/pin.md`, `reference/unpin.md`, or `reference/teach.md`, which do not exist upstream. It now routes `pin`/`unpin` to the Pin/Unpin section of `SKILL.md`, `teach` (an alias of `init`) to `reference/init.md`, `doctor` and `hooks` to their existing references, and every other command according to the skill's Commands table; no invented upstream playbooks are created.
- **Why:** AC-2 — expose `/impeccable` (freeform + upstream subcommands), a `/design` freeform alias, and one `/design-<command>` per upstream command without a TypeScript dispatcher. No absolute path or project-relative `.pi/skills` path is baked into any template.
- **Reproduced by:** `scripts/transform.mjs` `freeformTemplate()` / `commandTemplate()`.

## T2 patches (managed engine)

### P-6: Managed engine runner and `impeccable_run` tool

- **Files:** `index.ts` (new), `src/resources.ts` (new), `src/engine.ts` (new), root `package.json` (registration).
- **Change:** a typed engine module resolves resources from `import.meta.url`, pins `VERSION 0.1.18` and the exact upstream checksums from `skills/impeccable/scripts/engine-checksums.txt`, selects the correct released platform asset (darwin arm64/x64, linux arm64/x64, windows x64 with the documented ARM fallback), and runs the engine through a cancellable spawn with direct argv (never shell interpolation), bounded stdout/stderr capture, and the upstream `IMPECCABLE_SKILL_DIR`/`IMPECCABLE_SELF` context. Selection is: a deliberate `IMPECCABLE_BIN` trusted override (reported as unverified), the verified version-pinned cache, or an atomically staged, digest-verified download; ambient executables are never selected. Detector exit 2 is reported as `findings`; other nonzero exits keep their failure diagnostics. Timeouts, cancellation, and excess output kill the child and never produce a clean truncated success.
- **Registration:** `index.ts` initially registered `impeccable_run`; T3 adds the three adapters below. It remains listed in `pi.extensions` immediately before pika. Nothing fetches, spawns, asks questions, or writes project files at module activation.
- **Why:** AC-3 and this task's part of AC-10 — a managed, verified, cancellable engine path that retains the upstream prerequisite/fallback story and never treats a missing prerequisite as success. Detector hook and live-event runtime integrations remain later tasks.
- **Not reproduced by `transform.mjs`:** the runner is hand-written TypeScript that lives beside the generated skill; the generated skill text only names `impeccable_run` as the preferred path.
