# Pi runtime adapters

Use these rules for every Impeccable native command and engine directive. Engine output retains its source operations; these rules adapt harness interaction and delegation. Never turn missing UI or visual evidence into an approval.

## Questions and visual decisions

Use impeccable_question for 1–5 related material questions: stable question ids, question text, optional description, choices with stable ids/labels/descriptions, and allowFreeText when a custom answer is useful. With no choices it opens free-text input. Pi select/input dialogs work in TUI and RPC without a custom terminal component. A No choice is an actual answer; confirm is not used. Only invoke when a workflow asks, never at startup.

The result distinguishes answered, dismissed (dialog closed or timed out), cancelled (tool abort), and unavailable (no working dialog UI). It retains actual partial answers and pending questions; no selection or default is assumed. On any pending material decision, ask those questions in chat and wait. Do not continue unattended, record an assumed answer, or write an approval flag. A user may explicitly delegate a choice in actual words; record those words and the scope, never infer delegation from silence.

Retain serve-question direction/surface boards and component/asset review pages, including schemas, catalogs, image display, re-roll/update/wait procedures, and real ANSWER records. Use impeccable_run with separate argv entries. For long waits, use bounded calls and retain the same key. Closing a page unanswered is not approval. Use impeccable_question only at the playbook's supported fallback boundary; disclose the substitution. If both page and dialogs fail, show options and URLs in chat and wait for an actual answer. A text selector alone does not display a comp; retain image display or report the visual blocker.

## Existing Agent delegation

Use impeccable_delegate with role asset-producer, documenter, finish-reviewer, manual-edit-applier, assessment-a, or assessment-b. Supply a self-contained task packet and artifactPaths/contextPaths. It loads the WHOLE adapted canonical role (or complete critique playbook), resolves installed resource paths, and dispatches existing Agent types. Canonical role files are instruction resources, not globally installed agent types. If the adapter cannot call Agent on this Pi version, use its exact main-session Agent handoff when exposed. If no child was dispatched because Agent or the configured type is disabled/unavailable, disclose the actual failure and follow the upstream degraded/inline path; never describe it as independent review. The Agent schema's prose type list is only a startup snapshot; actual dispatch validates the current fleet. Do not enable agents, package roles, workflows, or alter user settings to work around this.

Requests are foreground, inherit_context:false, isolated:false: a fresh conversation retains installed extension/MCP tools. isolated:true strips those tools and is not fresh-context isolation. Models, tiers, and execution policies belong to the user's agent definitions; no raw model fields or hardcoded models. Agent configuration can override request flags/turn bounds: inspect returned effective tags, limits, status, output and usage, disclose conflicts, and do not claim isolation or completion that was not achieved. Agent's max_turns is a soft steering limit that permits grace turns. The adapter requests exactly the canonical role ceiling N and synchronously cancels when foreground progress reaches N at turn_end, before another turn can execute tools. Because this progress cannot distinguish a terminal answer from a continuation, even a final answer at that boundary is conservatively retained as partial/cancelled; no extra grace turn rescues it. Compatible configured soft limits at or below N are accepted without changing user configuration; excessive limits or incompatible execution policies still trigger cancellation. Final actual counts above N are rejected even if progress was absent. Respect cancellation, including a child independently stopped through /agents while the caller signal remains live; retain its partial output and stop the task without inline substitution. Assess actual child evidence before accepting it; terminal status alone never verifies the role contract. Fleet safety policies still apply; the supplied role controls this bounded task and its output format.

A completed result preserves native completion but still requires evidence assessment. A wrapped-up result preserves native steered: the child terminated after soft-limit wrap-up within the canonical budget, possibly with complete output or partial work. A compatible shorter configured soft limit is not a policy conflict. Inspect its actual output and changed artifacts against the role contract; never treat wrap-up as delegation unavailability or automatically repeat the role. A partial result preserves a terminal error, type substitution, policy conflict or a final count at/above the role ceiling without observed boundary cancellation. Retain actual partial artifacts and limitations; do not label this independently verified or completed. These executed outcomes set childTerminated:true, evidenceAssessmentRequired:true and inlineSubstitutionAllowed:false, retain native details under agent, and supply a reason. Cancellation reasons distinguish caller cancellation, user stop, role boundary and native hard-limit abort; cancellation stops this task. Error flags disclose terminal errors/conflicts without authorizing replay. For remaining work after a wrapped-up/partial result, inspect first and explicitly bound a handoff to the remaining work, preserving role policies and human checkpoints. These result rules govern upstream inline/respawn suggestions: automatic full-role inline fallback is reserved for confirmed no-child cases, never for a child that already executed.

An active result means Agent detached a child, for example because configured run_in_background:true overrode the request. Retain its actual agentId. Caller cancellation cannot stop that child, and cancelling get_subagent_result only cancels the wait. Do not perform inline substitution, duplicate its work, or start dependent work until it has stopped or settled. Use the returned get_subagent_result handoff when callable, or /agents to stop/manage it; if its ID is missing, locate it through /agents. Inspect the actual terminal output and policies before accepting a result. No automatic fallback is authorized while a writer may still be active.

Nested child-safe Agent currently returns text-only results without effective policies, terminal status, or progress updates. The adapter identifies its tool metadata and returns the complete main-session handoff BEFORE dispatch, for foreground and configured background children alike. Return that packet to the main session; do not execute it against the same nested Agent. A recognized pre-spawn unknown/disabled-type refusal for the requested type, with undefined details and no progress, returns unavailable with the actual message and upstream fallbackPath: no child was created, so disclosed inline substitution is allowed where the playbook permits. Other unexpected text-only results or exceptions AFTER dispatch return unresolved, including failed boundary cancellation without established termination: preserve actual output, inspect management/results to establish termination, and do not substitute inline work or launch a duplicate. Unknown termination is not delegation unavailability.

Finish-reviewer resumes currently return a handoff without dispatch: Agent's foreground resume path does not forward progress updates, so the adapter cannot monitor the role budget. Main session: inspect the stored reviewer's effective policies and actual partial evidence before any separately managed continuation; max_turns is a soft limit, not a hard cutoff. Prefer a fresh finish-reviewer with the complete recaptures and prior fixes, omitting resume, or disclose the upstream degraded review. A handoff is not a completed continuation or verdict.

- asset-producer: worker, ceiling 24 turns. Pass the measured spec, approved comp, scripts path and assigned regions; or the complete single decision-card comp packet, PRODUCT.md, shared frame, visualize.md, world images, verbatim COMPS mode rules and declared output path. Decision comps may delegate; the later three-comp round remains in the build thread as visualize.md directs.
- documenter: worker, ceiling 30. Pass project root, artifact paths, direction contract, PRODUCT.md, document.md, existing DESIGN.md and write boundary.
- finish-reviewer: reviewer, ceiling 30. Pass original request, actual confirmed answers, supplied captures, artifact, direction contract, PRODUCT.md, findings, QUALITY BAR images, approved comp or labeled critique reference, craft floor, build state/spec/diffs where applicable, platform references and no-detector line for native. The reviewer inspects supplied evidence only; it never starts a browser. For a verdict continuation, supply its actual id with recaptures and prior material fixes; follow the managed-continuation handoff above before any direct resume. Never resume a critique assessment.
- manual-edit-applier: worker, ceiling 12. Pass the leased event id, page URL, chunk/deadline, literal batch, repair/evidence paths, scripts and repository root, canonical JSON contract. The parent owns polling and protocol replies; the child edits only source.
- assessment-a: reviewer for supplied evidence/read-only assessment; set needsBrowser:true to use worker when live browser work is needed. Pass the resolved target and relevant source/capture paths, ignore rules, mode and context. Never include detector findings or sibling results.
- assessment-b: worker, ceiling 30, because detector/browser evidence may start a disposable helper. Pass the stable target, URL, constraints and cleanup requirements; no Assessment A results. It must report actual detector/browser operations and failures.

Launch critique A and B as separate individual requests with inherit_context:false, never a shared context or scripted workflow. They must not see each other's results before synthesis. Parallel individual calls are appropriate for independent evidence; desktop apps serialize A then B to avoid driving one window together. Complete A before consuming detector output in synthesis. Native critique uses A alone under the upstream platform exception. If either delegation could not dispatch, report the degraded method with the concrete reason; for an executed assessment inspect the actual output and limitations and bound any remaining assessment work before synthesis. Do not fabricate dual-agent provenance.

Workers share the current checkout so actual assets, documentation and leased source edits land at expected paths. Await writers before dependent work. Parallel decision-card writers must own distinct output paths; serialize overlapping writes. A git worktree copy cannot see uncommitted evidence and requires explicit path/artifact transfer; do not silently choose it for these roles.

## Browser, image and catalog capabilities

Call impeccable_capabilities when needed; it inspects CURRENT tool metadata without credential access or service requests. Image/browser matches are candidates, not established availability; absence is unknown. Read candidate tool schemas/help and establish what can actually run. Codemode may expose image models indirectly: inspect its model/tool discovery and help before deciding native generation is absent. Deferred tools may need discovery/activation. Reinspect when capabilities change.

Prefer harness-native image generation/editing, then the upstream generate-image fallback if its prerequisites are met. A missing engine API key says only that this fallback is unavailable; it says nothing about native image tools or codemode models. Never read or expose personal credential values. Preserve crops as references, exact output paths, native transparency checks, embed-prompt and prompt sidecars. Catalog cards and QUALITY BAR boards remain visual evidence: download/view through available tools as upstream directs; report inaccessible references and their effect on review.

Retain browser inspection, fresh tabs, screenshots, mutation preflight and helper cleanup. A read-only evaluate API cannot inject the overlay. Missing browser or image prerequisites must take the playbook's supported fallback with a concrete disclosure; a skipped visual step is not success. Native ios/android/adaptive targets use simulator/emulator captures and platform references; never run web detect/overlay against native source. This inspection tool does not implement a browser or image service.

## Pi session-owned live transport

Read reference/pi-runtime.md and the complete upstream live/generate playbook. Use impeccable_live action:start with argv containing native live arguments, or action:generate with argv containing native live-generate arguments (omit the verb). These return promptly while boot/Go waits run in background. Finish ordinary prerequisites, actual CSP consent and browser injection as the upstream playbook directs; a background start is not a successful browser boot. Inspect status/result for config, context, drift, browser and provenance instructions. Do not retry a refused start unattended.

This owner is the only consumer. Every native directive to live-poll, --stream, --then-poll, --reply or live-complete routes through impeccable_live. Never run foreground Bash ten-minute polling or another poll/helper, including when live-generate returns an already leased event. impeccable_run live/live-generate/live-poll/live-server/live-complete gives an explicit owner handoff. Other native source/scaffold/insert/variant/config commands still use impeccable_run with their exact argv. Read complete raw engine instructions, applying this transport rule to auxiliary/role instructions too.

One event carries pending.id and pending.eventToken. Handle generate in the parent with the action reference, identity/plan/knobs, supplied scaffold, screenshots/provenance, locks and native source application intact. Publish through impeccable_live action:reply, exact id/eventToken, status:done and file:<exact source or manifest>. Steer uses status:steer_done plus a source file or intentional no-op message. Mount failure repairs use done + file; failure uses error + message. Prefetch uses read without a native reply. No event is an approval for unrelated edits or bypassing native refusals.

Manual Apply retains the literal batch, page, evidence and deadlineMs (relative soft duration from pending.receivedAt). Delegate only bounded source work to manual-edit-applier with the remaining budget; the parent alone owns the reply. Pass its exact structured JSON as data with status:done: status, appliedEntryIds, failed, files and notes, retaining partial/error detail. Never replace it with summary counts or run live-commit-manual-edits for a leased apply event.

Accept/discard already include native _acceptResult and _completionAck. Inspect both. Plain complete/discarded acknowledgements must not be sent twice: perform accept-time verification separately, then reply status:verified with concrete evidence in message. Native carbonize requires all upstream cleanup and verification, then reply status:complete + evidence (also for carbonize_cleanup). The owner calls live-complete and checks the actual journal. Failed completion acknowledgements and agent_done/manual-fallback accepts retain upstream status/resume/manual cleanup, then use complete + evidence; native source_locked/receipt conflicts still require the upstream diagnostic or explicit native retry, never unattended replay. Never infer success from exit 0, repair a native journal to force success, or automatically acknowledge an unhandled event.

Use status to inspect and stop to cancel owned pollers/helper, retaining native journals, variants and source. /impeccable-live status|stop|resume works immediately without a model turn. Abort, queued user input, reload, branch/session switch, fork and shutdown invalidate delivery tokens and release owned resources; reused helpers, app servers and other sessions survive. An episode that settles with pending work pauses truthfully. Explicit resume uses this exact session's active-branch entries and native status/resume/journal, without another Go. A fork or shared cwd cannot adopt a parent's work. Wrong/stale ids, changed helper identity, malformed/oversize JSON, nonzero exits, business refusals, mismatched acks and remaining pending settlement pause for inspection, with no unattended retries or replay. Inspect actual native state before a new action.

Large complete bounded native payloads live in private OS temporary sidecars outside the project. Read payloadPath before acting; model output is never a JSON transport. Above the 4 MiB raw capture bound, truncated JSON is rejected and recovery uses the canonical native journal. Delivery is bounded to one actionable event per episode and 64 remembered events. Busy sessions use supported Pi boundaries; peers without those boundaries pause for explicit status/resume instead of claiming automatic delivery. Engine/helper resolution is lazy; native source transactions and locks remain authoritative, and no project/config/native-file queue is held across the live lifetime.


## Project detector and management

Use impeccable_run for hooks, ignores, doctor, pin and compatibility operations. The Pi operation adapter leaves raw engine stdout intact (including doctor JSON); integration metadata distinguishes adapter-only controls from actual engine execution. Runtime update/install/link redirects to this repository's vendoring procedure. Managed and fallback launchers explicitly set IMPECCABLE_PROVIDER_ID=pi and retain installed skill/self paths.

Automatic checks are off without explicit project opt-in. /impeccable hooks on enables successful native/nested edit/write feedback; off disables it and reset clears hook runtime controls and detector ignores while preserving unrelated product/visual settings and other harness commands. Shared/local precedence, consent and legacy disabled/quiet/log flags apply. Ignore operations use upstream validation; do not create broad exceptions to quiet tests or hide real findings. Read hooks.md for the suppression ladder and local/shared/file-scoped reasons.

Management cwd and session cwd must be existing accessible directories; project directory aliases resolve to their physical identity before selection. Management targets accept --target X, --target=X and -t X (last supplied target wins), with existing paths taking precedence over unique workspace basenames. Bare selectors, including dotted or leading-dot names and a single segment already absolutized against cwd, require exact unique workspace discovery; excluded, missing or ambiguous names fail before management writes. Discovery applies the declaring repository's exclusions and explicit project boundaries before following any child Git boundary; direct existing paths retain their separate precedence. A new source-file target requires an existing explicit parent and must retain that parent's project boundary; otherwise supply an existing app/parent path. Config, owned prompt and Git-exclude transactions share Pi's native mutation queue and bounded process locks. First creation uses Pi's lexical queue key; missing destinations through aliases are refused before staging because native physical-path writers use a different key. Use the physical destination reported by the refusal. Recursive workspace targets select the nearest package boundary, then the shallow app boundary, regardless of nested design/config markers. Hook controls establish local-config Git privacy before writing consent: canonical config/repository containment and Git's actual ignore result must be established. Escaping config destinations and already tracked local configs are refused; an exclusion cannot make tracked data private, and the adapter never changes the index. Automatic hook child exclusion maintenance holds the same exclusion-file transaction through child exit, including scans in sibling workspaces. Conflicts refuse stale replacements. Cancellation stops later commits and reports actual paths in integration.committed with integration.partial:true when earlier files committed; inspect them before retrying. Peers lacking the public mutation queue refuse management writes without raising the peer minimum. Detector defaults and isolated validation directories live in private OS temporary storage and are removed by their owner; explicitly configured audit logs retain their selected destination.

The upstream hook owns immediate tiers, completion deep passes, conservative attribution, dedup and preview-marker skips. Configured extensions accept strings or ext objects with upstream whitespace/dot normalization. An audit error (including detector-threw with exit 0 and empty stdout) reports missing detector coverage and does not request correction. Pi bounds execution/feedback and corrective continuation (one per invocation), respects abort/queued input and removes owned session state at shutdown. Web detector findings are inapplicable on ios/android/adaptive, never a clean native scan. On Pi without actionable boundary events, report missing automatic completion/continuation and run manual detect when needed. Pi's live owner shares the upstream preview-marker suppression; detector scans do not replace live accept-time verification.

Doctor retains real artifact findings and applicable --json/--fix/--target behavior, alongside truthful Pi hook metadata because upstream cannot discover this external package. Mutating doctor --fix first validates the selector through the same management context and executes with the canonical selected root as cwd. Only an explicitly supplied target becomes canonical --target, recorded by integration.originalTarget and integration.effectiveTarget. Targetless calls preserve target absence and omit those fields, retaining upstream workspace rows/findings. Read-only doctor/context preserve upstream flags and errors even if Pi metadata cannot resolve a selector. Cancelled doctor results retain actual engine outcomes; the adapter's config commit list does not establish whether upstream artifact fixes changed files. When integration.hooks.enabled is true on a Pi runtime with actionable boundary events, its automatic passes supply detector coverage; the upstream context MANUAL_DETECTOR_REQUIRED directive reflects missing foreign manifests and must not cause a second duplicate scan. Preserve the directive in raw output and explain this integration metadata when relevant. Pin uses the session cwd's .pi/prompts for project shortcuts or the agent prompts directory for user shortcuts, independently of engine cwd/target/root selection, checks public command discovery and ownership, recognizes a discovered prompt as the owned destination only by canonical existing file identity (including lexical symlink discovery paths), refuses all other command conflicts, and requires /reload. /design-* remains canonical. teach aliases init; craft retains its deprecated ordinary-new-work playbook. /i aliases /impeccable only when public discovery finds the canonical prompt and no existing /i command. If discovery cannot establish safety, use the canonical prompt and report the limitation.
